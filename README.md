## Vultr 후기에서 반복되는 장점과 단점

검색되는 후기들의 평가는 꽤 뚜렷하게 갈린다. 가격 대비 성능과 사용 편의성에는 점수가 높고, 장애 대응이나 기술 지원에는 아쉬운 소리가 섞인다.

먼저 좋다는 평가에 나오는 항목들이다.

- **가격**: 대부분 리전에서 월 $5부터 시작하고, 애틀랜타·뉴욕의 일부 플랜은 $2.5부터 제공된다.
- **서버 생성 속도**: VPS 생성이 보통 30초에서 1분 안에 끝난다.
- **관리 편의성**: 웹 기반 콘솔(noVNC)로 별도 프로그램 없이 서버 화면을 보고 작업할 수 있다. 방화벽 설정을 잘못해서 SSH 연결이 끊겼을 때도 웹 콘솔로 복구할 수 있다는 게 실사용 후기에서 자주 언급되는 장점이다. 모바일에서도 관리가 되지만 콘솔 조작은 다소 불편하다.
- **업타임**: 100% 노드·네트워크 가동률을 SLA로 내걸고 있고, 5분 이상 다운되면 그에 상응하는 크레딧을 보상한다. 과거 도쿄 리전에서 약 1시간 다운된 사건 때 크레딧 보상을 지급한 사례가 알려져 있다.
- **리전 수**: 공식 기준 33개 글로벌 데이터센터 리전. 서울과 도쿄 모두 있다.
- **시간 단위 과금**: 서버를 삭제하면 이후 요금이 발생하지 않는다. 짧게 쓰고 지우는 테스트 서버에 유리하다.
- **OS 선택 폭**: Ubuntu, Debian, CentOS, Fedora CoreOS, OpenBSD, Windows 등 기본 이미지가 다양하고, ISO 파일 직접 업로드도 지원한다.

아쉽다는 평가 쪽은 이렇다.

- 서울 리전의 네트워크가 해외를 경유한다(아래에서 자세히 다룬다).
- 전원을 꺼둔 서버도 요금이 나간다.
- 지원은 티켓 방식이며, 장애 대응 속도에 실망한 사용자 후기도 있다.
- 스냅샷이 무료가 아니고, 백업 옵션의 적용 범위에 예외가 있다.

## 서울 리전의 실제 모습 — "이름만 한국 서버"인 부분

서울 리전의 데이터센터는 실제로 한국에 있지만, 접속 네트워크가 해외 리전 트랜짓을 거쳐 도달한다. 2024년 8월 기준으로 국내 접속 시 주로 일본·동남아 쪽을 경유하는 것이 확인됐고, 실제로 한국 VPS에서 핑을 찍어봐도 일본 VPS와 차이가 없다는 평가가 있다. 한국어 후기에서 이 문제를 가장 자주 거론하는 지점이기도 하다.

한 배포 가이드를 쓴 작성자는 "핑을 제외하면 서울보다 도쿄의 네트워크 속도가 더 좋았다"고 적었다. 이 작성자는 Cloudflare 무료 CDN을 쓴다면 그냥 도쿄를 고르라고까지 권하는데, 무료 요금제에서는 한국 엣지 서버를 제공하지 않아 트래픽이 일본을 경유하기 때문이다.

그렇다면 서울 리전은 언제 의미가 있을까. 서비스 정책상 데이터가 국내에 위치해야 하는 경우처럼, 물리적 데이터 위치 자체가 필요할 때다. 순수하게 속도만 따지면 도쿄도 충분히 좋은 선택이고, 방문자가 한국인뿐인 서비스라면 두 리전의 체감 차이는 생각보다 작을 수 있다. 반대로 서울 리전 선택 시 유의할 점은 초과 트래픽 단가다. 서울은 기본 트래픽을 넘기면 GB당 $0.05가 추가되는 리전 중 하나다.

## 실제 후기에서 나오는 평가들

후기들을 읽다 보면 공통으로 등장하는 인상이 있다. 나무위키 문서에서는 "순전히 가성비와 프로모션으로 승부하는 회사"라는 평가가 예전에 있었지만, 요즘은 업타임이 거의 100%에 가깝고 가장 많이 사용되는 VPS 업체 중 하나로 평가가 옮겨갔다고 정리한다.

한 개발 블로그는 5년 이상 Vultr를 쓰면서 안정성과 속도에 만족했고, 자기 블로그를 2년 넘게 서버 장애 없이 운영했다고 밝혔다. 이 작성자가 특히 좋다고 짚은 부분은 비밀번호 초기화나 서버 업그레이드를 신청 절차 없이 대시보드에서 직접 처리할 수 있다는 점이었다.

반면 앞서 언급한 벨로그의 배포 가이드에서는 회사 네트워크나 서비스 장애 시 대처가 미흡하다는 이야기가 사용자들 사이에 있다는 점을 언급하면서, 작성자 본인도 직접 겪고 분노한 적이 있다고 썼다. UI 접근성이 좋아 초보 가입자에게 인기 있다는 평가와 이 지적이 같은 글에 공존한다. 지원은 티켓 시스템 기반인데, 처리 시간이 짧고 안정적이라는 평가와 별개로 장애 상황에서의 대응은 별개 문제라는 뜻으로 읽힌다.

## 가입 전에 알아두면 아끼는 과금 포인트

Vultr의 과금 구조에서 가장 많이 실수하는 지점들은 대부분 요금 페이지보다 도움말이나 후기에서나 확인되는 것들이다. 결제 전에 아래 여섯 가지를 확인하면 나중에 당황할 일이 줄어든다.

1. **전원을 꺼도 과금된다.** 시간 단위로 요금이 계산되지만, 전원을 꺼둔 서버도 자원을 계속 점유한 것으로 간주해 요금이 그대로 나간다. 과금을 멈추는 유일한 방법은 삭제다. "안 쓸 때는 꺼두면 되겠지"라고 생각했다면 여기서 걸러야 한다.
2. **스냅샷은 유료다.** 2021년 10월 1일부터 GB당 월 $0.05가 청구된다. 서버당 최대 11개까지 저장 가능하고, 스냅샷을 찍은 서버보다 낮은 사양의 서버에는 복원할 수 없다.
3. **백업 옵션에 블록스토리지는 빠져 있다.** 배포 시 추가하는 자동 백업 옵션이 블록스토리지까지 커버하지 않으므로, 블록스토리지 백업이 필요하면 다른 방법을 마련해야 한다.
4. **Windows Server는 라이선스 요금이 추가된다.** 라이선스를 이미 보유하고 있다면 ISO 업로드(최대 8GB, 2개까지)로 설치해 비용을 피할 수 있는데, Windows 설치 이미지에는 VirtIO 드라이버가 없어서 별도 통합 작업이 필요하다.
5. **리전별 초과 트래픽 단가가 다르다.** 서울과 호주는 1GB당 $0.05다. 트래픽이 많을 것으로 예상되는 서비스라면 리전 선택 시 이 항목도 계산에 넣자.
6. **프로모션 크레딧에는 기한이 있다.** 아래 섹션에서 다루지만, 받은 크레딧을 정해진 기간 안에 쓰지 않으면 소멸된다.

## 첫 서버 배포 과정은 어려운가

어렵지 않다. 실제 배포 가이드들이 공통으로 "초보도 따라 할 수 있다"는 취지로 서술할 정도로 절차가 단순하다. 순서는 이렇다.

1. 회원가입 후 메일 인증, 결제 수단(신용카드) 등록.
2. 대시보드에서 Product → Compute 선택, Deploy New Server 클릭.
3. 처음이라면 Cloud Compute - Shared CPU 유형을 고른다.
4. 지역을 고른다. 한국 서비스라면 도쿄 또는 서울. 위에서 설명한 네트워크 경유 문제를 감안하면 두 리전 모두 후보가 된다.
5. OS 이미지를 고른다. 배포 가이드 작성자의 경험상 직접 이미지를 첨부해 설치하면 에러를 잡는 게 꽤 골치 아프므로, 제공되는 기본 이미지를 쓰는 쪽이 수월하다.
6. 요금제를 고른다. 일반적인 용도라면 단일 코어 주파수가 높은 High Frequency가 낫다는 평가가 있다.
